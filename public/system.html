Architecture at scale
50,000 auctions · 200,000 watchers on one lot
ClientsREST for bids, WebSocket for updates
WS gateways ×20~10k sockets each, stateless
Pub/SubRedis / NATS, 1 channel per lot
Lot ownerssharded by lot id, single writer
Bid logappend-only, replayable
  • One owner per auction. Lots are sharded by id; every bid for a lot goes to one writer (Redis Lua script or one Kafka partition). No distributed locks, and lots run in parallel.
  • The bid check is one atomic step. Check open, check ≥ price + increment, resolve auto-bids, write, extend the deadline. All in one step, so two bids can never both see the old price.
  • The server clock decides. The deadline is checked inside that same step. A timer closes the lot exactly once; a late timer can't let a bid in after the end.
  • Fan-out separated from bidding. Owners publish to pub/sub; stateless gateways push to watchers, coalesced to ≤10 msgs/sec per lot with full state, so 200k watchers cost one fan-out per batch.
  • Durable, auditable log. Commands are appended before acknowledging; a crashed owner replays the log to rebuild the exact same state (try restarting the server).
  • Safety at the edges. Idempotent bid ids for retries, per-bidder rate limits, integer money, and authentication at the gateway.
